# EV Charge Book UI/UX 设计

版本: v1.3.0
更新时间: 2026-08-27

## 1. 设计目标

关键词: 简洁、清晰、低录入成本、数据可信、长期可用、Dark First。

v0.5 在不改变 Local First 核心原则的前提下，将原型式 Material 页面统一为新能源车数据 Cockpit 视觉语言。

基本约束：

- 真实数据不足时显示未知/空状态，不生成实时 SOC、剩余续航或不存在的车辆事实
- Dark First 默认，Light 可显式切换并持久化
- 视觉优化不能破坏 Trip/定位/备份等可靠性语义
- 不为视觉效果引入不必要的重型框架

---

## 2. 当前一级信息架构

v0.5 使用五个一级入口：

```text
总览
记录
统计
行程
车辆
```

底部导航使用扁平黑底 + 绿色选中状态，不使用默认 Material 大面积选中胶囊。

二级页面继续承担新增/编辑/详情/车型目录/蓝牙/数据工具等流程，不增加更多底部 Tab。

---

## 3. Dashboard / 总览

Dashboard 是“当前车辆 + 本月能源 + 最近充电”的主入口。

### Hero Vehicle

优先展示：

- 品牌 / 车型
- 精确匹配到的本地车辆图
- 用户车辆中已保存的电池容量
- 标称续航

不展示未经真实数据源提供的：

- 当前 SOC
- 当前剩余续航
- SOH
- 车辆在线状态

当前支持的本地车辆图覆盖：BYD 海豹、零跑 C16、小米 SU7、Tesla Model 3。其他车型使用统一 fallback，不允许错配近似车型。

车辆图随 APK 打包，不依赖运行时网络或 Base64 解码。

### 能源与最近记录

Dashboard 继续展示本月费用/补能等真实账本指标以及最近充电记录。数据不足时使用紧凑空状态，而不是空白大卡片。

---

## 4. 充电记录

Records 使用账本 Cockpit + 时间轴结构。

每笔记录优先表达：

- 日期时间
- 地点
- SOC 起止
- 补入电量
- 费用
- 单价
- 充电类型 / 里程（存在时）

Add/Edit 继续支持时间、SOC、电量、费用、类型、地点、备注及可用的位置能力。

定位失败不能阻塞保存，用户仍可手工填写地点；坐标/地址事实边界由 Location 相关设计文档和 Issue #66/#14 继续约束。

---

## 5. 行程 UX

Trip 是 v0.5 的一级核心页面。

### READY

开始前明确当前车辆、定位准备状态和开始操作，避免记录到错误车辆。

### LIVE

驾驶中只保留必要且可信的信息：

- 已记录时长
- 可信距离
- 速度指标（有可靠来源时）
- GPS 健康状态
- 结束行程

不鼓励驾驶中复杂交互。

### INTERRUPTED

服务/定位链路中断时必须明确展示中断状态和恢复/收口语义，不能伪装成正常连续记录。

### 详情

行程详情展示：

- 真实轨迹形状
- 起止时间
- 距离
- 总耗时 / 行驶时间
- 平均速度 / 最高已记录速度
- GPS gap / 可信度说明
- 海拔信息仅在数据来源可靠时展示并明确 GNSS 来源

大型 GPS gap 不允许画成可信连续实线。

---

## 6. 统计 UX

Stats 按层级组织，而不是继续堆等权卡片：

1. 本月能源 Cockpit
2. 月环比 / 月趋势
3. 充电方式 / 常用地点
4. 累计账本
5. 里程区间估算与 Trip 覆盖证据

所有派生/估算指标应继续和原始事实区分，不使用“真实车辆能耗”等会误导来源的文案。

---

## 7. 我的车辆 / Garage

当前车辆使用与 Dashboard 相同的 Hero 语言。

多车辆采用列表/切换器：

```text
当前车辆
其他车辆
连接与数据
```

单车管理：

- 设为当前车辆
- 编辑
- 归档

有历史数据时优先归档，不鼓励破坏性删除。

车型目录始终保留“找不到 -> 自定义添加”兜底。目录和车辆图片当前只覆盖部分车型，不代表完整车型数据承诺；扩充由 #20 负责。

---

## 8. Theme / Appearance

默认：Dark。

用户可以在车辆页切换 Light，并持久保存。

Dark / Light 必须保持相同信息结构和状态语义。

当前 v0.5 baseline 不要求“跟随系统”第三模式；未来如增加，应作为显式 Appearance 选项。

---

## 9. 权限、后台与隐私 UX

定位权限只在相关能力使用时请求。

持续 Trip 记录必须：

- 有 foreground service / ongoing notification
- 用户知道何时正在记录
- 锁屏不泄露精确地址/经纬度
- GPS/权限/后台限制异常有明确可修复入口

更完整的锁屏、权限撤销、电池优化提示继续由 #26 跟踪。

---

## 10. 状态设计

必须覆盖：

- 无车辆
- 无充电记录
- 无行程记录
- 车型图不支持 -> fallback
- 定位权限拒绝
- 等待 GPS fix
- GPS 有坐标但地址仍在解析
- GPS/定位不可用
- 轨迹存在 gap
- Light/Dark 下 warning/error 可读

状态不能只靠红/黄/绿等颜色传达，必须结合文字或图标。

---

## 11. 可用性与无障碍 hardening

PR #71 完成的是视觉与信息层级 baseline，不等于以下真机边界已完成：

- fontScale 1.3 / 1.5
- 320-360dp 小屏
- TalkBack 顺序和语义
- icon-only action 的 contentDescription
- >=48dp touch target
- 超长地点/车型/蓝牙名称
- IME 遮挡和长表单焦点滚动
- dirty form 返回保护
- active Trip 状态下恢复备份/归档/切车等数据安全 guard

这些项目统一由 Issue #42 跟踪，避免继续用纯视觉 PR 掩盖真实 usability 风险。
